## 第 6 周：微服务完善 + 配置中心 + 服务治理

### 第 6 周 星期一（第 26 天）
- **今日目标**：Nacos 配置中心统一管理各服务配置 + 配置热更新
- **项目改造任务**：
  - 修改文件：`blog-cloud/blog-gateway/pom.xml`（新增 Nacos Config）
    ```xml
    <dependency>
        <groupId>com.alibaba.cloud</groupId>
        <artifactId>spring-cloud-starter-alibaba-nacos-config</artifactId>
    </dependency>
    ```
  - 新建文件：`blog-cloud/blog-gateway/src/main/resources/bootstrap.yml`
    ```yaml
    spring:
      application:
        name: gateway-service
      cloud:
        nacos:
          config:
            server-addr: localhost:8848
            file-extension: yaml
    ```
  - 在 Nacos 控制台 → 配置管理 → 新建配置：
    ```
    Data ID: gateway-service.yaml
    配置内容：写 gateway 路由规则
    ```
  - 添加 `@RefreshScope` 注解（后续给配置类加上）
  - 预期效果：修改 Nacos 中的配置，不重启服务即可生效
- **核心知识点**：
  - 学习内容：配置中心的作用（动态配置/环境隔离/配置审计）、bootstrap.yml 加载顺序（比 application.yml 优先）、@RefreshScope 热刷新
  - 学习资源：[Nacos Config 官方文档](https://nacos.io/zh-cn/docs/quick-start-spring-cloud.html)（读 Spring Cloud 整合部分）
- **LeetCode刷题**：
  - 题目：[200. 岛屿数量](https://leetcode.cn/problems/number-of-islands/)（考察：DFS/并查集）
- **今日检查项**：
  - [ ] Nacos 中修改配置后，服务不重启就生效
  - [ ] bootstrap.yml 配置正确，服务能启动
- **常见问题与解决方案**：
  - bootstrap.yml 不加载：Spring Boot 3.x 需手动添加 `spring-cloud-starter-bootstrap` 依赖
  - 配置没热更新：确认类上有 `@RefreshScope` 注解

### 第 6 周 星期二（第 27 天）
- **今日目标**：Sentinel 流量控制 + 熔断降级（保护文章服务）
- **项目改造任务**：
  - 修改文件：`blog-cloud/blog-article-service/pom.xml`
    ```xml
    <dependency>
        <groupId>com.alibaba.cloud</groupId>
        <artifactId>spring-cloud-starter-alibaba-sentinel</artifactId>
    </dependency>
    ```
  - 修改文件：`blog-cloud/blog-article-service/src/main/resources/application.yml`
    ```yaml
    spring:
      cloud:
        sentinel:
          transport:
            dashboard: localhost:8080  # Sentinel 控制台地址
          eager: true
    ```
  - 新建文件：`blog-cloud/blog-article-service/.../config/SentinelConfig.java`
    ```java
    @Configuration
    public class SentinelConfig {
        @Bean
        public SentinelResourceAspect sentinelResourceAspect() {
            return new SentinelResourceAspect();
        }
    }
    ```
  - 修改文件：`blog-cloud/blog-article-service/.../controller/ArticleController.java`
    ```java
    @GetMapping("/list")
    @SentinelResource(value = "articleList", 
                      blockHandler = "listBlockHandler",
                      fallback = "listFallback")
    public Result<Page<Article>> getAllArticles(...) { ... }
    
    // 限流后执行
    public Result<Page<Article>> listBlockHandler(...) {
        return Result.error("请求太频繁，请稍后重试");
    }
    ```
  - 预期效果：文章列表接口被限流时返回友好提示
- **核心知识点**：
  - 学习内容：Sentinel 核心概念（资源/规则/流控模式/熔断降级）、与 Hystrix 对比、Sentinel Dashboard 安装
  - 学习资源：[Sentinel 官方文档 - 流量控制](https://sentinelguard.io/zh-cn/docs/flow-control.html)（读基本概念 + Spring Cloud 整合）
- **LeetCode刷题**：
  - 题目：[46. 全排列](https://leetcode.cn/problems/permutations/)（考察：回溯算法）
- **今日检查项**：
  - [ ] Sentinel Dashboard 能显示服务接口
  - [ ] 配置限流规则后，超限请求返回"请求太频繁"
- **常见问题与解决方案**：
  - Sentinel Dashboard 连接失败：先启动 Dashboard（`java -jar sentinel-dashboard.jar`）
  - blockHandler 方法签名必须和原方法匹配（加 BlockException 参数）

### 第 6 周 星期三（第 28 天）
- **今日目标**：Seata 分布式事务实战（评论 → 积分增加 → 异步通知，保证最终一致性）
- **项目改造任务**：
  - 修改文件：`blog-cloud/blog-article-service/pom.xml`
    ```xml
    <dependency>
        <groupId>com.alibaba.cloud</groupId>
        <artifactId>spring-cloud-starter-alibaba-seata</artifactId>
    </dependency>
    ```
  - 修改文件：`blog-cloud/.../service/impl/CommentServiceImpl.java`
    ```java
    @Override
    @GlobalTransactional(name = "create-comment-tx", rollbackFor = Exception.class)
    public Comment createComment(Long articleId, Long userId, String content, Long parentId) {
        // 1. 保存评论
        Comment comment = new Comment();
        comment.setArticleId(articleId);
        comment.setUserId(userId);
        comment.setContent(content);
        comment.setParentId(parentId);
        comment.setCreateTime(LocalDateTime.now());
        comment = commentRepository.save(comment);
        
        // 2. 远程调用用户服务，给评论者加积分（模拟）
        // userFeignClient.addScore(userId, 5);  // 评论一次 +5 分
        
        // 如果上面抛出异常，评论也会回滚
        return comment;
    }
    ```
  - 预期效果：评论和加积分在同一个全局事务中，任一失败都回滚
- **核心知识点**：
  - 学习内容：Seata AT 模式原理（全局事务/分支事务/undo log）、TCC 模式、Saga 模式
  - 学习资源：[Seata 官方文档 - AT 模式](https://seata.io/zh-cn/docs/dev/mode/at-mode.html)（读核心原理）
- **LeetCode刷题**：
  - 题目：[236. 二叉树的最近公共祖先](https://leetcode.cn/problems/lowest-common-ancestor-of-a-binary-tree/)（考察：递归/DFS）
- **今日检查项**：
  - [ ] Seata Server（TC）启动成功
  - [ ] 注释掉的事务管理能正常提交和回滚
- **常见问题与解决方案**：
  - Seata 端口冲突：默认 8091 端口，改 `file.conf` 中的配置
  - undo_log 表必须存在：在数据库中执行 `CREATE TABLE undo_log` 建表脚本
