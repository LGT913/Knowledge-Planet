## 六、状态机与并发控制

### 问题 12：代取订单有哪些状态？怎么防止状态被改乱？

**问题本身**：
> 问：代取订单有哪些状态？
> 追问：怎么防止状态被改乱（比如已取件后被取消）？
> 再追问：校验放哪层？
> 再追问：同一个快递被两人同时签收怎么办？
> 再追问：怎么测试并发场景？

**为什么要这么做**：
- 状态机确保业务流程的正确性
- 并发控制防止状态被并发修改导致数据不一致

**具体怎么做**：

**代取订单状态流转**：
| 状态 | 含义 | 操作 | 角色 |
|------|------|------|------|
| 0-待分配 | 学生发布代取订单 | 学生发布 | 学生 |
| 1-待取件 | 代取员接单 | 代取员/管理员 | 代取员/管理员 |
| 2-已取件 | 代取员已取到快递 | 代取员 | 代取员 |
| 3-已完成 | 用户收到快递 | 代取员 | 代取员 |
| 4-已取消 | 订单被取消 | 学生/管理员 | 学生/管理员 |

**状态流转校验（Service 层）**：
```java
public void updateStatus(Integer id, Integer status) {
    DeliveryOrder order = deliveryOrderMapper.findById(id);
    if (order.getStatus() == 3) {
        throw new BusinessException("订单已完成，不能修改");
    }
    if (status == 1 && order.getStatus() != 0) {
        throw new BusinessException("只有待分配的订单才能接单");
    }
    // ... 其他状态校验
}
```

**并发控制（UPDATE 带状态条件）**：
```sql
UPDATE delivery_order SET status=3 WHERE id=? AND status=2
```
- 利用数据库原子性保证只有一个请求成功
- 返回受影响行数：1 成功，0 说明状态已被他人改过

**多线程并发测试**：
```java
ExecutorService pool = Executors.newFixedThreadPool(2);
CountDownLatch latch = new CountDownLatch(1);

pool.submit(() -> {
    latch.await();
    deliveryOrderService.cancel(orderId);  // 线程1：取消
});
pool.submit(() -> {
    latch.await();
    deliveryOrderService.pickup(orderId);  // 线程2：取件
});

latch.countDown();  // 同时触发
pool.shutdown();
```

**项目实战**：
- 代取订单状态流转严格按顺序
- UPDATE 带状态条件防止并发冲突
- 权限双层校验（Controller + Service）

**如何验证**：
1. 测试状态非法流转（如已完成→取消），验证返回错误
2. 用多线程模拟并发操作，验证只有一个成功
3. 查询数据库确认最终状态一致
