### D.2 ⚠️ 面试回答禁忌

| 不要 | 要 |
|------|----|
| 说"项目没用过"就结束 | 说"虽然项目没用，但我知道..." |
| 说"忘记了" | 说"这个点我需要确认一下..." |
| 说"这样就行了" | 说"目前这样做够用，但后续可以考虑..." |
| 只讲技术不讲场景 | 先讲业务场景，再讲技术方案，最后说为什么这么选 |
| 只讲理论不关联项目 | 每个知识点都要关联项目中的具体应用 |

### D.3 ⚠️ 易混淆/易忘知识点清单

| 知识点 | 易错点 | 正确理解 |
|--------|--------|---------|
| 联合索引 vs 单列索引 | 以为联合索引"更小" | 联合索引多列，空间更大，但组合查询更高效 |
| 代取订单"已取件" | 说成"未完成" | 2-已取件（代取员已取到快递，正在派送中） |
| 统计优化瓶颈 | 以为是数据库慢 | Java Stream 过滤占 90% |
| 权限校验 | 只放 Controller | 双层防护：Controller 快速拦截 + Service 兜底 |
| 密码返回前端 | 觉得"加密了就行" | 加密密码也不返回，用 VO 过滤 |
| 乐观锁 | 以为手动比较 | UPDATE SET version=version+1 WHERE version=? |
| 登录查全表 | 觉得"数据少没关系" | 用 findByUsername() 查单条 + 建索引 |
| TCP 三次握手 | 说不清为什么三次 | 防止失效连接请求到达服务端 |
| Maven 插件 | 以为是普通插件 | spring-boot-maven-plugin 打可执行 jar |
| HTTP 无状态 | 以为指 TCP 无连接 | 指服务器不记录请求历史 |
| #{} vs ${} | 搞混哪个防注入 | #{} 预编译防注入，${} 字符串拼接有注入风险 |
| BCrypt vs MD5 | 以为 BCrypt 更快 | BCrypt 更慢（可调工作因子），但抗暴力破解能力强 |

### D.5 面试高频追问链（⚠️ 重点复习）

> 以下是根据面试对话梳理的连环追问链，面试官通常会从一个点开始逐层深入。

**追问链 1：统计优化**
```
你做了什么优化？
  → 具体哪个统计项？改前后SQL对比？
    → 2-3秒到50-80ms怎么测出来的？
      → 怎么判断瓶颈在Java过滤而不是数据库？
        → 怎么排除缓存影响？
```

**追问链 2：索引设计**
```
你建了哪些索引？
  → 为什么建联合索引(courier_id, status)不建两个单列？
    → 这个组合查询对应哪个业务场景？
      → 如果status=0数据涨到3000条+ORDER BY create_time DESC LIMIT 20呢？
        → EXPLAIN看什么字段判断索引是否生效？
```

**追问链 3：状态流转 + 并发**
```
代取订单有哪些状态？
  → 怎么防止状态被改乱（比如已取件后被取消）？
    → 校验放哪层？权限放Controller，状态放Service？
      → 批量签收或定时任务绕过Controller怎么办？
        → 同一个快递被两人同时签收怎么办？
          → 怎么测试并发场景？
```

**追问链 4：数据库设计**
```
设计了6张表，什么关系？
  → 代取订单完整链路涉及哪些表？
    → 收件人信息为什么冗余不外键？
      → 快递员信息为什么外键不冗余？
        → express表扁平化设计有什么缺点？
```

**追问链 5：缓存（Redis）**
```
给文章详情加缓存怎么设计？
  → 更新时先更新DB再删缓存，删缓存失败怎么办？
    → 缓存穿透/击穿/雪崩怎么应对？
      → 博客系统选重试+过期时间还是MQ？为什么？
```

**追问链 6：接口开发**
```
拿一个接口走完整流程？
  → 登录接口有什么问题？
    → 全表查用户的风险？怎么改？
      → 直接返回User对象的安全问题？怎么改？
        → 权限校验和状态校验怎么分层？
```
