##### 1.博客的文件

**前端 axios + encodeURIComponent 把中文编码成 UTF-8 → Tomcat 默认 `URIEncoding=UTF-8` 解码 URL → Jackson 默认 UTF-8 解析 JSON body → Spring Boot 默认 `encoding.force=true`强制响应 UTF-8 → MySQL 8 默认 utf8mb4 存储。** 只有绕过 Spring 直接写 response 的地方（JwtInterceptor）才需要手动 setContentType("...;charset=utf-8")。

```
┌─────────────┐    JSON body / URL?keyword=中文    ┌──────────────┐
│  Vue 前端    │─────────────────────────────────▶ │ Tomcat (内嵌) │
│ axios+UTF-8 │                                    │  URIEncoding │
└─────────────┘                                    │  =UTF-8 默认  │
                                                   └──────┬───────┘
                                                          │
                                  ┌───────────────────────┴───────┐
                                  ▼                               ▼
                          @RequestBody                     @RequestParam
                          (@Json)                          (@PathVariable)
                                  │                               │
                                  ▼                               ▼
                          Jackson 解析                       Spring 已解码
                          默认 UTF-8                         完成（无需处理）
                                  │                               │
                                  └───────────────┬───────────────┘
                                                  ▼
                                          Service / Repository
                                                  │
                                                  ▼
                                    MySQL (utf8mb4 默认字符集)
```

##### 2.`#{}` 和 `${}` 的区别？

`#{}` 预编译防注入；`${}` 字符串直接拼接，存在 SQL 注入风险，一般仅用于动态表名、排序字段。



##### 3.注解开发能不能写动态 SQL？

可以，使用 `<script>` 标签包裹 SQL，但是代码可读性差，生产复杂查询优先 XML。



##### 4.SpringBoot 整合 MyBatis，为什么不需要手动创建 SqlSessionFactory？

回答：`mybatis-spring-boot-starter` 提供了自动配置类 `MybatisAutoConfiguration`，容器检测到 DataSource 存在时，自动创建 SqlSessionFactory、SqlSessionTemplate，实现零配置。



##### 5.事务的概念与用法

事务就是用来解决数据直接 “乱套”这种问题的：**把多个操作打包成一个 “要么全成功、要么全失败” 的整体，不允许中间状态存在**。

**四大特性**： 

-  原子性（Atomicity）

​       盒子里的操作是不可分割的原子，要么都成功，要么都失败，不存在 “部分成功”。

​     （转账的两步必须同时完成或同时撤销）

- 一致性（Consistency）

​      事务执行前后，数据的整体状态必须保持一致。

​    （转账前后，你和朋友的总余额不变，不会凭空少钱 / 多钱）

- 隔离性（Isolation）

​     多个事务同时执行时，互相之间不会干扰，一个事务看不到另一个事务的中间状态。

   （你转账的同时，别人给你转账，两个操作不会互相影响导致数据混乱）

- 持久性（Durability）

​     事务一旦提交成功，数据就永久写入数据库，哪怕系统崩溃也不会丢失。

   （转账成功后，这笔记录会永久保存在数据库里，不会消失）

**用法**：1.开启事务支持：在你的启动类上加上 `@EnableTransactionManagement`

​         2.给业务方法加 `@Transactional` 注解：如果有多个数据库操作，就可以加这个注解

**事务什么时候会回滚？（核心规则）**

  Spring 事务默认**只对 RuntimeException（运行时异常）和 Error 回滚**，对检查型异常（Exception）不回滚。

  如果想让所有异常都回滚，可以修改注解：@Transactional(rollbackFor = Exception.class)

**事务的传播行为（进阶理解）**

  简单说，就是**一个带事务的方法，调用另一个带事务的方法时，事务怎么处理**。

  举个最常用的例子：

-  REQUIRED（默认值）：如果当前没有事务，就新建一个；如果已经有事务，就加入这个事务。

​       就像你在一个盒子里，再放一个小盒子，两个盒子里的操作共用一个事务，要么一起提交，要么一起回滚。

##### 6.Maven

面试题：项目中为什么使用 Maven 多模块？

**标准回答**：

在企业级 SpringBoot 项目中使用 Maven 多模块，主要为了：

1. **代码复用**：抽取公共工具、实体类为通用模块，避免重复编码；
2. **分层解耦**：按领域、分层拆分模块，职责单一，便于团队协作维护；
3. **统一依赖管理**：通过父工程统一管控所有依赖版本，减少 Jar 包冲突；
4. **提升构建与部署效率**：局部修改只编译对应模块，微服务场景可独立打包、独立部署。

2.追问：父工程中 `dependencies` 和 `dependencyManagement` 区别？

- `dependencies`：父工程声明后，**所有子模块自动继承**，强制引入；

- dependencyManagement：仅声明版本，不会自动引入，子模块需要时再手动引入，只统一版本号。企业多模块优先用 dependencyManagement。

3.追问：多模块打包顺序？

   Maven 会根据模块依赖关系自动排序：被依赖的模块先编译打包，依赖别人的后执行。



##### 7.Docker

###### 一、Docker 是什么

**一句话**：Docker 把你的应用 + 依赖 + 操作系统环境一起打成一个"箱子"（镜像），搬到任何机器上都能直接跑，不会出现「在我电脑上能跑」的问题。
