## 七、Redis 缓存设计

### 问题 13：给文章详情接口加缓存怎么设计？

**问题本身**：
> 问：如果给文章详情接口加缓存，你会怎么设计？
> 追问：更新时怎么处理缓存？
> 再追问：数据库更新成功但删除缓存失败怎么办？
> 再追问：缓存穿透、击穿、雪崩怎么应对？

**为什么要这么做**：
- 缓存减少数据库压力，提升接口响应速度
- 旁路缓存模式（Cache-Aside）是最常用的缓存策略
- 需要处理缓存一致性、缓存失效等问题

**具体怎么做**：

**读取流程（旁路缓存模式）**：
```
1. 查 Redis：GET article:{id}
2. 命中 → 直接返回
3. 未命中 → 查 DB → SET article:{id} (过期时间30分钟) → 返回
```

**更新流程**：
```
1. 先更新数据库
2. 再删除缓存（不是更新缓存！）
```

**缓存删除失败兜底**：
```java
int retry = 3;
while (retry > 0) {
    try { redisTemplate.delete(key); break; }
    catch (Exception e) { retry--; Thread.sleep(100); }
}
// 过期时间兜底
redisTemplate.opsForValue().set(key, article, 30, TimeUnit.MINUTES);
```

**缓存问题应对**：

| 问题 | 现象 | 应对 |
|------|------|------|
| 穿透 | 查不存在的数据，每次直达 DB | 缓存空值（短过期5分钟）+ 参数校验 |
| 击穿 | 热点 key 过期瞬间，大量请求打到 DB | 互斥锁 + 热点数据永不过期 |
| 雪崩 | 大量 key 同时过期 | 过期时间加随机值 + 多级缓存 |

**项目中可应用场景**：
| 场景 | 缓存 key | 缓存值 | 过期时间 |
|------|---------|--------|---------|
| 系统配置 | config:{key} | config_value | 1小时 |
| 登录状态 | session:{userId} | User 对象 | 30分钟 |
| 统计数据 | stats:today_orders | COUNT 结果 | 5分钟 |

**如何验证**：
1. 首次请求查数据库，后续请求查缓存
2. 更新数据后，缓存被删除，下次请求重新加载
3. 模拟缓存删除失败，验证过期时间兜底生效
4. 模拟缓存穿透（查不存在的数据），验证缓存空值生效
