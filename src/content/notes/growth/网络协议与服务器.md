## 7. 网络协议与服务器

### 7.1 HTTP 协议

- HTTP 是**无状态**的应用层协议，基于 TCP
- 请求结构：请求行（方法+URL+版本）→ 请求头 → 请求体
- 响应结构：状态行（版本+状态码）→ 响应头 → 响应体
- 常见状态码：200/400/401/403/404/500

**项目应用**：`@PostMapping`/`@GetMapping` 映射接口，统一 Result 返回，`@RequestParam`/`@RequestBody`/`@PathVariable` 接收参数。

### 7.2 TCP 协议

- **三次握手**：SYN → SYN+ACK → ACK（防止已失效连接请求到达服务端）
- **四次挥手**：FIN → ACK → FIN → ACK（服务端可能还有数据没发完，ACK 和 FIN 分开）

> ⚠️ **易忘点**：为什么三次不是两次？——两次无法防止已失效的 SYN 到达服务端建立无效连接。为什么四次不是三次？——服务端的 ACK 和 FIN 可能不同时发（中间可能还有数据）。

### 7.3 Socket

- 应用层与 TCP/IP 通信的中间抽象层
- 通信流程：服务端 bind → listen → accept → read/write；客户端 connect → read/write
- HTTP 底层基于 Socket 实现

### 7.4 Tomcat

- Spring Boot 内嵌 Tomcat（`spring-boot-starter-web`），默认 200 线程
- 打 jar 包直接 `java -jar` 运行，不需要外部 Tomcat
- 排查：线程池耗尽 → 调 `server.tomcat.max-threads`；`jstack` 查 BLOCKED 线程

**项目应用**：application.yml 配置 `server.port: 8080`。

### 7.5 Nginx

- **反向代理**：客户端 → Nginx → Tomcat
- **负载均衡**：轮询/权重/IP hash
- **静态资源**：Nginx 处理，Tomcat 只处理动态请求

**排查**：502 → Tomcat 挂了；504 → 后端超时；看 access.log/error.log。

**项目应用**：单体架构未用 Nginx，生产环境可在前面加 Nginx 做反向代理和静态资源处理。

## 8. 工程化工具（Maven / Git）

### 8.1 Maven

- POM 文件：项目坐标、依赖、构建插件
- 生命周期：`clean → compile → test → package → install → deploy`
- **spring-boot-maven-plugin**：打可执行 jar 包（内嵌 Tomcat），没有它 jar 不能直接运行

**项目应用**：pom.xml 继承 `spring-boot-starter-parent:2.7.18`，核心依赖包括 starter-web、mybatis-spring-boot-starter、mysql-connector-java、spring-boot-starter-security。

> ⚠️ **易忘点**：`spring-boot-maven-plugin` 不是普通插件，它的作用是 repackage，把普通 jar 打成可执行 jar（内嵌 Tomcat + 依赖库）。

### 8.2 Git & SVN

| 对比项 | SVN（集中式） | Git（分布式） |
|--------|--------------|--------------|
| 仓库 | 中央服务器 | 每人完整仓库 |
| 离线 | 不支持 commit | 支持 |
| 分支 | 较重 | 轻量指针 |

**面试话术**：项目用 Git 管理代码，也了解 SVN。Git 分布式+轻量分支适合协作；SVN 集中式+严格权限适合权限控制要求高的场景。

## 9. 文档编写 & 沟通协作

### 9.1 文档编写

> 对应岗位职责："编写用户手册、安装手册、操作手册"

1. **接口文档**：每个接口写清请求路径、方法、参数（字段名/类型/必填）、返回示例
2. **数据库设计文档**：schema.sql 每张表每个字段都加 COMMENT 注释
3. **部署说明**：构建、配置数据库、启动步骤

### 9.2 前后端协作流程

1. 开发前：一起评审接口文档，对齐字段名、类型、请求方式
2. 开发中：后端先写好接口，Postman 自测通过，把接口文档给前端
3. 联调时：前端联调发现问题，配合排查
4. 上线前：全链路测试，确保核心流程跑通
