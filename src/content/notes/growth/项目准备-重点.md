## 七、项目准备（重点）

### 1. 项目介绍（2分钟版本）

> "我做的项目是一个**基于 Spring Boot + Vue3 的前后端分离博客系统**。
> 
> 后端技术栈是 Spring Boot 3 + Spring Data JPA + MySQL + Redis，前端是 Vue3 + Vite + Tailwind CSS。
> 
> 项目主要有四个模块：
> 1. **用户模块**：注册登录，用 JWT 做身份认证
> 2. **文章模块**：文章的增删改查，我给文章详情和列表加了 Redis 缓存来减轻数据库压力
> 3. **分类模块**：文章分类管理
> 4. **评论模块**：文章评论功能
> 
> 整个项目我独立完成了前后端的开发，中间也遇到了不少问题，比如 Redis 的序列化配置、跨域问题，最后都一一解决了。"

---

### 2. 项目高频问题

**Q1：为什么要用 Redis 做缓存？**

> "因为博客系统的文章列表和详情页是典型的读多写少场景，直接查数据库压力大。用 Redis 做缓存后，热点数据直接从内存取，响应速度快很多，也减轻了数据库压力。"

**Q2：缓存和数据库一致性怎么保证的？**

> "我用的是**先更新数据库，再删除缓存**的策略。
> 
> 为什么不先删缓存？因为如果先删缓存，还没来得及更数据库，这时候有个读请求过来，会把旧数据又写回缓存，就脏了。
> 
> 先更数据库再删缓存，虽然理论上也有极小概率出现脏数据（比如一个读请求刚好在缓存刚被删、数据库还没更完的时间窗口进来），但概率非常低，而且缓存有过期时间，最终也会一致。
> 
> 如果要更严谨，可以用**延时双删**或者用 **Canal 监听 binlog 异步更新缓存**。"

**Q3：Redis 怎么用的？缓存策略是什么？**

> "我主要缓存了两块：
> 1. **文章详情**：key 是 `article:detail:{id}`，过期时间 30 分钟
> 2. **文章列表**：key 是 `article:list`，过期时间 10 分钟
> 
> 读的时候先查 Redis，命中直接返回；没命中就查数据库，然后写入 Redis。
> 
> 写的时候（创建/更新/删除文章），更新数据库后删除对应的缓存，让下次查询自动回源。"

**Q4：JWT 是怎么实现的？登录流程？**

> "登录流程是这样的：
> 1. 用户输入用户名密码，提交到后端
> 2. 后端校验用户名密码（密码用 BCrypt 加密比对）
> 3. 校验通过，生成 JWT token 返回给前端
> 4. 前端把 token 存在 localStorage，后续请求放在 Authorization 请求头里
> 5. 后端写了一个拦截器，对需要登录的接口校验 token，从 token 里解析出 userId
> 
> JWT 有三部分：header、payload、signature。我把 userId 存在 payload 里，用 HS256 算法签名。"

**Q5：JWT 和 Session 的区别？**

> "Session 是存在服务端的，有状态；JWT 是存在客户端的，无状态。
> 
> JWT 的好处：
> - 前后端分离、跨域方便
> - 服务端不需要存储，扩展性好，适合分布式部署
> 
> JWT 的缺点：
> - 一旦签发，没法主动作废（除非做黑名单）
> - payload 不能放敏感信息，因为是 base64 编码不是加密"

**Q6：遇到过什么难点？怎么解决的？**

选 1-2 个讲细：

**难点1：Redis 序列化问题**
> "一开始用默认的 JdkSerializationRedisSerializer，存到 Redis 里是一堆二进制乱码，看起来很不方便。
> 
> 后来我配置了 RedisTemplate，序列化器改成 Jackson2JsonRedisSerializer，key 用 String 序列化，value 用 JSON 序列化，这样 Redis 里存的就是可读的 JSON 了。"

**难点2：跨域问题**
> "前后端分离，前端 5173 端口，后端 8080 端口，存在跨域。
> 
> 我的解决方案是：
> 1. 开发环境：前端 Vite 配置 proxy 代理，把 /api 请求转发到后端
> 2. 生产环境：后端配置 CORS（WebMvcConfig 里 addCorsMappings），允许跨域访问"

**难点3：Spring Boot JPA 复杂查询**
> "一开始用 JPA 只知道简单的 findAll、findById，后来做文章列表按时间排序、按用户查询，我自己写了方法命名查询，比如 findByUserIdOrderByCreateTimeDesc，还学会了用 @Query 注解写 JPQL。"

### 3. 项目可以改进的地方（主动说加分）

> "当然这个项目还有很多可以改进的地方，比如：
> 1. **加上分页查询**，现在列表是全量查的，数据多了不行
> 2. **加上搜索功能**，按标题和内容搜索
> 3. **权限控制**，现在谁都能删别人的文章，应该校验作者
> 4. **缓存优化**，比如加布隆过滤器防穿透，加分布式锁防击穿
> 5. **评论支持多级嵌套**，现在只有一级"
