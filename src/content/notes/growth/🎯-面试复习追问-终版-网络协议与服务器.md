## 八、网络协议与服务器

### 问题 14：TCP 三次握手和四次挥手是什么？

**问题本身**：
> 问：TCP 为什么需要三次握手？
> 追问：为什么四次挥手不是三次？

**为什么要这么做**：
- 三次握手确保双方都具备发送和接收数据的能力，防止已失效的连接请求到达服务端
- 四次挥手是因为 TCP 是全双工通信，关闭连接时双方可能还有数据没发完

**具体怎么做**：

**三次握手**：
1. 客户端 → 服务端：SYN（请求建立连接）
2. 服务端 → 客户端：SYN+ACK（确认收到，同时请求建立连接）
3. 客户端 → 服务端：ACK（确认收到）

**四次挥手**：
1. 客户端 → 服务端：FIN（请求关闭连接）
2. 服务端 → 客户端：ACK（确认收到）
3. 服务端 → 客户端：FIN（请求关闭连接）
4. 客户端 → 服务端：ACK（确认收到）

**如何验证**：
1. 使用 Wireshark 抓包，观察 TCP 握手和挥手过程
2. 理解 SYN、SYN+ACK、ACK、FIN 等标志位的含义

### 问题 15：Nginx 和 Tomcat 有什么区别？

**问题本身**：
> 问：你了解 Nginx 和 Tomcat 吗？它们有什么区别？
> 追问：什么时候用 Nginx？什么时候用 Tomcat？

**为什么要这么做**：
- Nginx 是高性能 HTTP 反向代理服务器，擅长处理静态资源和负载均衡
- Tomcat 是 Java Web 应用服务器，擅长处理动态请求

**具体怎么做**：

| 对比项 | Nginx | Tomcat |
|--------|-------|--------|
| 类型 | HTTP 服务器/反向代理 | Java Web 应用服务器 |
| 擅长 | 静态资源、负载均衡、反向代理 | Servlet/JSP 动态请求 |
| 并发能力 | 极高（数万级） | 中等（数百级） |

**Nginx 典型配置**：
```nginx
upstream backend {
    server 192.168.1.101:8080;
    server 192.168.1.102:8080;
}

server {
    listen 80;
    location / {
        proxy_pass http://backend;
    }
    location /static/ {
        root /var/www;
    }
}
```

**项目实战**：
- 项目用 Spring Boot 内嵌 Tomcat
- 生产环境可在前面加 Nginx 做反向代理和静态资源处理

**如何验证**：
1. 启动 Spring Boot 项目，确认 Tomcat 正常运行
2. 配置 Nginx 反向代理，验证请求能正常转发
3. 验证静态资源由 Nginx 直接返回
