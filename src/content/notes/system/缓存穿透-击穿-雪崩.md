### 2.6 缓存穿透 / 击穿 / 雪崩

| 问题 | 本质 | 典型场景 | 解决方案 |
|------|------|---------|---------|
| 穿透 | 查询不存在的数据，缓存和数据库都没有 | 恶意攻击（查不存在的ID） | 布隆过滤器、空值缓存 |
| 击穿 | 热点 key 过期瞬间大量请求打到数据库 | 秒杀商品缓存过期 | 互斥锁、热点 key 永不过期 |
| 雪崩 | 大量 key 同时过期，请求全部打到数据库 | 批量缓存设置了相同过期时间 | 随机过期时间、多级缓存 |

#### 穿透：布隆过滤器、空值缓存

```java
// 布隆过滤器拦截不存在的 key
// 初始化时把数据库所有 ID 放入布隆过滤器
bloomFilter.put(1L);
bloomFilter.put(2L);

public Object getUser(Long id) {
    // 布隆过滤器判断不存在，直接返回，不查缓存和数据库
    if (!bloomFilter.mightContain(id)) {
        return null;
    }
    Object user = redis.get("user:" + id);
    if (user != null) {
        return user;
    }
    // 缓存未命中，查数据库
    user = db.queryById(id);
    if (user == null) {
        // 空值缓存，设短过期时间防止穿透
        redis.set("user:" + id, "", 60);
        return null;
    }
    redis.set("user:" + id, user, 3600);
    return user;
}
```

#### 击穿：互斥锁

```java
// 热点 key 过期时，用互斥锁只让一个线程去查数据库重建缓存
public Object getHotKey(String key) {
    Object value = redis.get(key);
    if (value != null) {
        return value;
    }
    // 获取互斥锁
    if (redis.setnx("lock:" + key, "1", 10, TimeUnit.SECONDS)) {
        try {
            // 双重检查
            value = redis.get(key);
            if (value != null) {
                return value;
            }
            value = db.query(key);
            redis.set(key, value, 3600);
            return value;
        } finally {
            redis.del("lock:" + key);
        }
    }
    // 等待后重试
    Thread.sleep(50);
    return getHotKey(key);
}
```

#### 雪崩：随机过期时间

```java
// 给缓存过期时间加随机值，避免同时过期
int expire = 3600 + random.nextInt(600);  // 3600~4200秒
redis.set(key, value, expire);
```

#### 面试题

**Q：缓存穿透、击穿、雪崩的区别和解决方案？**

A：三者都是缓存失效导致请求打到数据库，但触发条件不同。穿透是查询缓存和数据库都不存在的数据，每次都穿过缓存打到数据库，常见于恶意攻击，用布隆过滤器前置拦截或缓存空值解决。击穿是单个热点 key 过期的瞬间，大量并发请求同时打到数据库，用互斥锁（只让一个线程查库重建缓存）或逻辑过期（key 不设过期，后台异步更新）解决。雪崩是大量 key 同时过期，用随机过期时间打散过期点、多级缓存（本地 + Redis）兜底解决。核心区别：穿透是"查不存在的"，击穿是"热点 key 过期"，雪崩是"大量 key 同时过期"。
