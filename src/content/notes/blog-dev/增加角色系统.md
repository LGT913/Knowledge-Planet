# 增加角色系统

目前项目只有 JWT 鉴权（你是谁），没有授权（你能做什么）。加一个简单的角色系统，就能区分普通用户和管理员。

## 一、完整修正方案（6 个文件）

### 第 1 步：User 实体加 role 字段

修改 User.java：

```java
@Entity
@Table(name = "user")
public class User {
    // ... 现有字段不变

    @Enumerated(EnumType.STRING)
    @Column(nullable = false, length = 20)
    private Role role = Role.USER;   // 默认普通用户

    public enum Role {
        USER,
        ADMIN
    }
}
```

修改UserController.java：

```java
String token = jwtUtil.generateToken(loggedInUser.getId(), loggedInUser.getRole().name());

@PostMapping("/login")
public Result<Map<String, Object>> login(@RequestBody User loginRequest) {
        User loggedInUser = userService.login(loginRequest.getUsername(), loginRequest.getPassword());
        String token = jwtUtil.generateToken(loggedInUser.getId(), loggedInUser.getRole().name());
        Map<String, Object> data = new HashMap<>();
        data.put("user", loggedInUser);
        data.put("token", token);
        return Result.success(data);
}
```

注意：`loginRequest` 是前端请求对象，`loggedInUser` 是数据库查出来的完整用户。

### 第 2 步：UserPrincipal 改造

修改 UserPrincipal.java：

```java
@Getter
@ToString
@EqualsAndHashCode
public class UserPrincipal implements UserDetails {

    private static final long serialVersionUID = 1L;

    private final Long userId;
    private final String role;

    public UserPrincipal(Long userId, String role) {
        this.userId = userId;
        this.role = role;
    }

    @Override
    public Collection<? extends GrantedAuthority> getAuthorities() {
        // 关键：Spring Security 约定角色前缀 ROLE_
        // 数据库存 USER/ADMIN，这里加前缀变成 ROLE_USER / ROLE_ADMIN
        return List.of(new SimpleGrantedAuthority("ROLE_" + role));
    }
    //..剩下不变
}
```

### 第 3 步：JwtUtil 加方法

修改 JwtUtil.java：

#### 3.1 generateToken 加 role 参数

```java
public String generateToken(Long userId, String role) {
    return Jwts.builder()
            .subject(userId.toString())
            .claim("role", role)          // 新增：存角色
            .issuedAt(new Date())
            .expiration(new Date(System.currentTimeMillis() + expirationTime))
            .signWith(key)
            .compact();
}
```

#### 3.2 加 getRoleFromToken

```java
public String getRoleFromToken(String token) {
    Claims claims = Jwts.parser()
            .verifyWith(key)
            .build()
            .parseSignedClaims(token)
            .getPayload();
    return claims.get("role", String.class);
}
```

### 第 4 步：JwtAuthenticationFilter 解析 role

修改 JwtAuthenticationFilter.java 第 51-53 行：

```java
// 3. token 有效 → 解析 userId + role，构造认证信息
Long userId = jwtUtil.getUserIdFromToken(token);
String role = jwtUtil.getRoleFromToken(token);   // 新增
UserPrincipal principal = new UserPrincipal(userId, role);
```

### 第 6 步：给接口加权限注解

#### 6.1 BloomFilterController 落地 TODO

修改 BloomFilterController.java 第 34 行：

```java
// 改前
//TODO: 加上 @PreAuthorize("hasRole('ADMIN')")
```

所有三个接口（stats、rebuild、check）都是管理员接口，可以在**类级别**加：

```java
@RestController
@RequestMapping("/api/admin/bloom")
@PreAuthorize("hasRole('ADMIN')")   // ← 类级别，所有方法都要管理员
public class BloomFilterController {
    // ...
}
```

#### 6.2 文章管理接口（可选）

ArticleController.java的 update / delete 也应该限制：

```java
@PutMapping("/update/{id}")
@PreAuthorize("hasRole('ADMIN')")   // 只有管理员能改任何文章
public Result<Article> updateArticle(...) { ... }

@DeleteMapping("/delete/{id}")
@PreAuthorize("hasRole('ADMIN')")
public Result<String> deleteArticle(...) { ... }
```

注意：create 接口普通用户也能发文章，不用加。

## 四、数据库迁移

你数据库里已经有用户了，需要加列并赋默认值：

```sql
ALTER TABLE user ADD COLUMN role VARCHAR(20) NOT NULL DEFAULT 'USER';
```

### 创建管理员账号

直接在数据库里改一条：

```sql
UPDATE user SET role = 'ADMIN' WHERE username = '你的管理员用户名';
```

## 五、思考

###### 1."为什么前端拦了，后端还要拦？"——这是**前后端双重校验**的安全设计：

| 防护层               | 作用                         | 绕过难度                  |
| :------------------- | :--------------------------- | :------------------------ |
| 前端路由守卫         | 普通用户看不到入口，体验更好 | 容易（手动输 URL）        |
| 后端 `@PreAuthorize` | 即使绕过前端，服务端拒绝     | 极难（需要 JWT 签名密钥） |

###### 2.**前端请求拦截** + **后端安全过滤链** + **前端路由守卫**三层机制，实现登录前后的网络配置差异。

| 防护层                     | 作用位置               | 控制什么           |
| :------------------------- | :--------------------- | :----------------- |
| 前端路由守卫               | Vue Router beforeEach  | 哪些页面能进       |
| 前端请求拦截               | api/index.js request() | 请求是否带 token   |
| 后端 Security Filter Chain | Spring Security        | 接口是否有权限访问 |

后端安全层：放行 vs 拦截

核心文件：SecurityConfig.java + JwtAuthenticationFilter.java

**后端的请求处理流程：**

```
                    请求到达
                      │
                      ▼
           ┌────────────────────┐
           │ JwtAuthentication  │
           │     Filter         │
           └─────────┬──────────┘
                     │
        ┌────────────┴────────────┐
        │ 有 token 且有效？        │
        └────┬──────────────┬─────┘
          是 │              │ 否（无 token / 无效）
             ▼              ▼
    ┌────────────────┐   放行（匿名状态）
    │ 写入 Security  │      │
    │ Context        │      │
    │ （带用户身份）  │      │
    └───────┬────────┘      │
            └───────┬───────┘
                    ▼
          ┌─────────────────────┐
          │  SecurityConfig     │
          │  authorizeRequests  │
          └─────────┬───────────┘
                    │
       ┌────────────┴─────────────┐
       │ 路径在 permitAll 列表？   │
       └─────┬───────────────┬───┘
          是 │               │ 否
             ▼               ▼
         直接放行       检查是否已认证
                      ┌──────┴──────┐
                    是 │           │ 否
                       ▼           ▼
                  进入Controller   返回 401
```

3.项目深度依赖 Spring Security，只是走的是**企业级自定义认证**而非默认用户：

| 功能         | 你的实现                                            | 所在文件                              |
| :----------- | :-------------------------------------------------- | :------------------------------------ |
| 请求过滤链   | `JwtAuthenticationFilter` 拦截所有请求              | JwtAuthenticationFilter.java          |
| URL 权限控制 | `permitAll()` / `authenticated()` / `@PreAuthorize` | SecurityConfig.java                   |
| 安全上下文   | `SecurityContextHolder.setAuthentication()`         | JwtAuthenticationFilter.java          |
| 方法级授权   | `@PreAuthorize("hasRole('ADMIN')")`                 | SiteConfigController.java             |
| 密码加密     | `BCryptPasswordEncoder`                             | SecurityConfig.java                   |
| 异常处理     | `AuthenticationEntryPoint` 统一返回 401             | SecurityAuthenticationEntryPoint.java |

你用的是 Spring Security 的**核心能力**，只是认证数据源从"内存默认用户"换成了"JWT Token + 数据库用户表"。

## 面试话术

>"我在 JWT 鉴权基础上加了角色授权体系。用枚举定义 USER 和 ADMIN 两个角色，存在 user 表的 role 字段。登录时把 role 放进 JWT 的 claim，JWT 过滤器解析后构造 `UserPrincipal`，`getAuthorities()` 返回 `ROLE_` 前缀的权限对象。接口层面用 `@PreAuthorize("hasRole('ADMIN')")` 做方法级权限控制。**设计要点**：`ROLE_` 前缀是 Spring Security 的约定，所以在转换层加前缀而不是存在数据库里，保持数据干净。"
