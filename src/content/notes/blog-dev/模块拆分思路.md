## 三、模块拆分思路

### 3.1 blog-common（公共模块）

**定位**：只放被多个服务共享的通用代码，不启动、不注册到 Nacos。

**包含**：
- `Result<T>` — 统一返回格式
- `PageResult<T>` — 分页返回
- `GlobalExceptionHandler` — 全局异常处理

**依赖最小化原则**：

```xml
<!-- 只需 spring-web 注解 + spring-data-commons 的 Page -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>
```

> 注意：这两个依赖在 Gateway 中会引入 Tomcat 和 JPA，需要排除。

### 3.2 blog-gateway（网关）

**职责**：统一入口、路由分发、跨域处理。

**关键设计决策**：

1. 不引入 Spring Security（鉴权由各服务自行处理，避免 Gateway 和业务服务双重鉴权冲突）
2. 排除 `spring-boot-starter-tomcat`（与 Netty 冲突）
3. 排除 `spring-boot-starter-data-jpa`（Gateway 不需要数据库）
4. 使用 SC 2025.0.0 新 key：`spring.cloud.gateway.server.webflux.*`
5. 公共配置 `blog-common.yaml` 从 Nacos 拉取，但不使用其中 JWT/DB/Redis 配置

**路由设计**：

```
/api/user/**    → lb://blog-user-service（8081）
/api/article/** → lb://blog-article-service（8082）
/api/category/** → lb://blog-article-service（8082）
/api/comment/** → lb://blog-article-service（8082）
```

### 3.3 blog-user-service（用户服务）

**职责**：用户注册、登录、JWT 签发、个人信息管理。

**迁移清单**：

| 从单体迁移 | 包路径变化 |
|-----------|-----------|
| `com.blog.blog.entity.User` | `com.blog.user.entity.User` |
| `com.blog.blog.repository.UserRepository` | `com.blog.user.repository.UserRepository` |
| `com.blog.blog.service.UserService` | `com.blog.user.service.UserService` |
| `com.blog.blog.controller.UserController` | `com.blog.user.controller.UserController` |
| `com.blog.blog.security.JwtUtil` | `com.blog.user.security.JwtUtil` |
| `com.blog.blog.config.RedisConfig` | `com.blog.user.config.RedisConfig` |
| `com.blog.blog.util.RedisUtil` | `com.blog.user.util.RedisUtil` |

**关键问题**：`JwtUtil` 放在 `security` 包而非 `util` 包——因为 JWT 是认证基础设施，属于安全域，不是通用工具。`controller` 依赖 `security` 层是合理的。

### 3.4 blog-article-service（文章服务）

**职责**：文章 CRUD、分类管理、评论管理。

**Phase 2 简化原则**（当前阶段）：

- 纯 JPA CRUD，不做 Redis 缓存
- 不做跨服务调用（查 User 昵称）
- 不做消息队列（RabbitMQ 通知）
- 评论的 `userId` 暂时由请求参数传入（Phase 3 改为从 JWT 解析）

**迁移清单**：

| 从单体迁移 | 包路径变化 |
|-----------|-----------|
| `com.blog.blog.entity.Article` | `com.blog.article.entity.Article` |
| `com.blog.blog.entity.Category` | `com.blog.article.entity.Category` |
| `com.blog.blog.entity.Comment` | `com.blog.article.entity.Comment` |
| `com.blog.blog.repository.*` | `com.blog.article.repository.*` |
| `com.blog.blog.service.*` | `com.blog.article.service.*` |
| `com.blog.blog.controller.*` | `com.blog.article.controller.*` |
