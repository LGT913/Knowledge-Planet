## 遇到问题与修复

### 修复 1：token.substring(0,12) 哈希碰撞

**问题描述**：最初的黑名单 key 使用 `token.substring(0, 12)`，两个不同 Token 前 12 位可能相同，导致正常用户被误拉黑。

```
Token_A = "eyJhbGciOiJIUzI1NiJ9...abc123def456"  → key = "eyJhbGciOiJIU"
Token_B = "eyJhbGciOiJIUzI1NiJ9...abc123def789"  → key = "eyJhbGciOiJIU"  ← 碰撞！
```

**修复方案**：JWT 签发时内置 `jti`（UUID），黑名单 key 使用 jti。

**经验**：不要截取 Token 字符串作为标识，Token 的前缀通常是固定的（算法头 + 载荷头），碰撞概率比想象中高。

---

### 修复 2：双写不一致 —— Redis 写入失败

**问题描述**：DB 保存成功，Redis 写入失败（网络超时），数据库已禁用用户，但 Redis 没有禁用标记，用户仍可访问。

**解决方案**：三步兜底

```
1. 顺序：先 DB（必保），后 Redis（尽力）
2. Redis 失败：catch 异常，记录日志，不阻断 DB 操作
3. 兜底：启动时 DisabledUserLoader 从 DB 恢复 Redis
```

**经验**：DB + Redis 双写不可能做到强一致性，采用"最终一致性"策略：DB 是真相源，Redis 是加速缓存，Redis 丢了可以从 DB 恢复。

---

### 修复 3：Redis 宕机无降级

**问题描述**：`redisUtil.hasKey()` 在 Redis 连接不上时直接抛出异常，导致所有请求都无法通过鉴权，全站 401。

**异常类型**：`RedisConnectionFailureException`（Spring Data Redis 封装）

**修复方案**：在 Filter 中 catch Redis 连接异常，降级查 DB。

```java
private boolean isUserDisabled(Long userId) {
    try {
        return Boolean.TRUE.equals(redisUtil.hasKey(USER_DISABLED_KEY + userId));
    } catch (RedisConnectionFailureException e) {
        // 降级查 DB
        Optional<User> userOpt = userRepository.findById(userId);
        return userOpt.map(u -> !u.getEnabled()).orElse(true);
    }
}
```

**经验**：任何外部依赖（Redis、MQ、DB）都可能在运行时不可用，关键路径必须有降级策略。没有降级的鉴权是单点故障。

---

### 修复 4：UserPrincipal 四个状态检查全部硬编码 true

**问题描述**：`UserPrincipal` 的 `isAccountNonExpired()`、`isAccountNonLocked()`、`isCredentialsNonExpired()`、`isEnabled()` 四个方法全部返回 `true`，等于关闭了 Spring Security 的账号状态检查功能。

```
@Override
public boolean isEnabled() { return true; }  // ❌ 永远返回 true
```

**修复方案**：不在 UserPrincipal 层面修复，而是在 Filter 层面做两层检查。因为 Spring Security 的这四个方法在自定义 Filter 体系下并不自动触发，在 Filter 中显式检查更可控。

**经验**：Spring Security 提供了钩子，但如果你不用 UsernamePasswordAuthenticationFilter 的标准流程，这些钩子不会自动触发。自己接管 Filter 后，所有检查都要显式写出。

---

### 修复 5：UserServiceImpl.register 没有设置 enabled

**问题描述**：注册方法创建 User 对象后，没有设置 `enabled` 字段，导致新用户 `enabled = null`，后续 Filter 查 `!u.getEnabled()` 时报 NullPointerException。

**修复方案**：注册时显式设置 `user.setEnabled(true)`。

```java
user.setEnabled(true);  // 注册时默认启用
```

**经验**：新增 DB 字段时，所有创建该实体的地方都要同步修改，漏掉任何一处就会产生 NULL 值和 NPE。
