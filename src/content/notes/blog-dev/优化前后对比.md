## 四、优化前后对比

### 4.1 架构对比

**优化前：**

```
用户发评论 → CommentServiceImpl.createComment()
                ├── 写 MySQL
                ├── 删 Redis 缓存
                └── 发 RabbitMQ 消息 → CommentNotifyConsumer
                                            └── TODO: 实际通知逻辑（空实现，只打印日志）
```

**优化后：**

```
用户发评论 → CommentServiceImpl.createComment()
                ├── 写 MySQL
                ├── 删 Redis 缓存
                └── 发 RabbitMQ 消息 → CommentNotifyConsumer
                                            ├── SETNX 幂等去重
                                            └── SimpMessagingTemplate.convertAndSend()
                                                    → STOMP Broker → /topic/article/{id}/comments
                                                            → 前端 SockJS → Toast 通知
```

### 4.2 代码对比

**CommentNotifyConsumer 优化前：**

```java
try {
    log.info("收到评论通知:文章ID={}, ...");
    // TODO: 实际通知逻辑(WebSocket 推送、邮件、站内信)
} catch (Exception e) {
    log.error("处理评论通知失败", e);
    throw new RuntimeException(e);
}
```

**CommentNotifyConsumer 优化后：**

```java
try {
    log.info("收到评论通知:文章ID={}, ...");
    String destination = String.format(COMMENT_TOPIC_TEMPLATE, message.getArticleId());
    messagingTemplate.convertAndSend(destination, message);
    log.info("WebSocket 推送成功, destination={}", destination);
} catch (Exception e) {
    log.error("处理评论通知失败", e);
    throw new RuntimeException(e);
}
```

### 4.3 用户体验对比

| 维度 | 优化前 | 优化后 |
|---|---|---|
| 新评论感知 | 必须手动刷新页面 | 实时 Toast 弹出 |
| 消息延迟 | 取决于用户刷新频率 | 通常 < 500ms |
| 用户体验 | 差，可能错过评论 | 好，实时通知 |
| 网络开销 | 无额外开销 | 一条 WebSocket 长连接 |

## 六、总结

### 6.1 技术选型总结

| 技术点 | 选择 | 替代方案 |
|---|---|---|
| 消息协议 | STOMP（基于 WebSocket） | 原生 WebSocket、SSE、MQTT |
| 降级方案 | SockJS | 无降级（不支持旧浏览器） |
| 消息代理 | SimpleBroker（Spring 内置） | RabbitMQ STOMP Plugin、ActiveMQ |
| 异步解耦 | RabbitMQ | 直接 WebSocket 推送、Kafka |
| 前端封装 | Vue 3 Composable | 直接在组件内写逻辑、Vuex/Pinia |

### 6.2 关键设计原则

1. **异步解耦**：评论创建与消息推送通过 RabbitMQ 分离，互相不影响
2. **幂等性**：Redis SETNX 防止重复推送，保证消息至少消费一次
3. **失败隔离**：推送失败不影响评论创建，推送失败进入死信队列可追溯
4. **渐进增强**：SockJS 兜底，不支持 WebSocket 时自动降级
5. **生命周期管理**：前端组件销毁时自动断开 WebSocket，防止内存泄漏

### 6.3 后续可扩展方向

| 方向 | 说明 |
|---|---|
| 认证 | 在 STOMP CONNECT 阶段添加 `ChannelInterceptor` 校验 JWT Token |
| 站内信 | 消费者同时写一条 `Notice` 记录到数据库 |
| 邮件通知 | 异步调用邮件服务，通知作者"您的文章有新评论" |
| 性能优化 | 高并发场景下，SimpleBroker 换为 RabbitMQ STOMP Plugin 做外部 Broker |
| 连接数监控 | 暴露 `/actuator/websocket` 端点，监控在线连接数 |
| 消息持久化 | 推送失败的消息写入 Redis List，定时重试 |
